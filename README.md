# KTT ระบบหลังบ้านงานรับเหมาก่อสร้าง

ระบบหลังบ้านครบวงจร: งานขาย ประมาณราคา โครงการ หน้างาน การเงิน จัดซื้อ คลัง ต้นทุน เจ้าหนี้ ภาษี และงานหลังการขาย (Phase 1–4)

| ส่วน | เทคโนโลยี |
|---|---|
| backend | Java 21, Quarkus 3 (REST, Hibernate Panache, Flyway, SmallRye JWT) |
| frontend | Angular 22 (standalone, signals, zoneless) + Angular Material 3 + Tailwind utilities |
| database | PostgreSQL 16 |

## โครงสร้าง

```
backend/    Quarkus API (com.ktt.*)
  src/main/resources/db/migration/   ตารางทั้งหมด (V1–V9)
frontend/   Angular
docs/       เอกสารออกแบบ (auth-design.md)
deploy/     ตัวอย่าง nginx และสคริปต์สำรองฐานข้อมูลสำหรับ production
```

## เริ่มพัฒนา

ต้องมี Java 21, Maven 3.9+, Node 22+, Docker

```bash
# 1) ฐานข้อมูล + Mailpit
docker compose up -d

# 2) backend  (http://localhost:8080, Swagger: http://localhost:8080/q/swagger-ui)
cd backend
mvn quarkus:dev

# 3) frontend (http://localhost:4200 ส่ง /api ไป :8080 ผ่าน proxy.conf.json)
cd frontend
npm install
npm start
```

เข้าสู่ระบบครั้งแรกด้วย `admin@ktt.local` / `Admin@12345` ระบบจะให้ตั้งรหัสผ่านใหม่ แล้วตั้ง 2FA ด้วยแอป Authenticator (บทบาท owner บังคับใช้)

ในโหมด dev อีเมลรีเซ็ตรหัสผ่านไม่ถูกส่งจริง ลิงก์จะแสดงใน log ของ Quarkus (`[DEV] Password reset link ...`)

## ทดสอบ

```bash
cd backend && mvn test                     # unit test (TOTP, Argon2, เลขผู้เสียภาษี)
cd backend && mvn test -Dtest=AuthFlowIT   # ทดสอบ flow login ครบ กับ PostgreSQL จริง (ต้องมี Docker)
cd frontend && npx ng test --watch=false
```

## สิ่งที่ทำแล้ว

**พื้นฐาน**
- ระบบ auth ครบ: login, 2FA (TOTP + รหัสสำรอง), refresh token rotation, จัดการ session, ลืม/เปลี่ยนรหัสผ่าน, ล็อกบัญชี, rate limit, RBAC, audit log (รายละเอียดใน [docs/auth-design.md](docs/auth-design.md))
- ผู้ใช้ บทบาทและสิทธิ์ ประวัติการใช้งาน บัญชีของฉัน แจ้งเตือนในระบบ ตั้งค่าบริษัท/โลโก้/ลายเซ็น

**Phase 1 งานขายและประมาณราคา**
- ลูกค้า, Lead Kanban + กิจกรรม + ไฟล์แนบ, ฐานราคากลาง + Excel
- BOQ หลายระดับ + แม่แบบ + แบบ ปร.4/ปร.5 พร้อม Factor F
- ใบเสนอราคา เลขที่ `INV ปปดด-NNN` (พ.ศ.), Revision, ส่วนลด 0–15% พร้อมขออนุมัติ, หน้าพิมพ์ตามฟอร์มบริษัท

**Phase 2 บริหารโครงการและการเงินฝั่งขาย**
- แปลงใบเสนอราคาที่ลูกค้าอนุมัติเป็นโครงการ + สัญญาในคลิกเดียว
- สัญญา งวดงาน (ส่งมอบ → วางบิล → รับเงิน) เงินล่วงหน้า เงินประกันผลงาน หัก ณ ที่จ่าย
- งานเพิ่ม-ลด (VO) พร้อมขออนุมัติ ปรับมูลค่าสัญญา ขยายเวลา และสร้างงวดเรียกเก็บอัตโนมัติ
- แผนงาน Gantt (หมวด/งานย่อย น้ำหนักงาน งานก่อนหน้า หมุดหมาย) และ S-Curve แผนเทียบจริง
- รายงานประจำวันสำหรับมือถือ (คนงาน อากาศ ความคืบหน้างาน รูปจากกล้อง) แจ้งเตือนโฟร์แมน 17:30 ถ้ายังไม่ส่ง
- ปัญหา/ความเสี่ยง, Punch list, ตรวจ QC ตามแม่แบบ, บันทึกความปลอดภัย, เอกสารโครงการ
- เอกสารการเงิน: ใบแจ้งหนี้, ใบแจ้งหนี้/ใบกำกับภาษี, ใบวางบิล, ใบเสร็จ, ใบเสร็จ/ใบกำกับภาษี (ออกอัตโนมัติเมื่อรับชำระ), ใบลดหนี้, ยกเลิกเอกสาร
- ลูกหนี้คงค้างตามอายุหนี้ และรายงานความคืบหน้าสำหรับพิมพ์ส่งลูกค้า

### หลักการคำนวณภาษีของเอกสารขาย
งานรับเหมาเป็นงานบริการ ภาษีขายเกิดเมื่อได้รับชำระ จึงแนะนำให้ออก "ใบแจ้งหนี้" ตอนวางบิล แล้วระบบออก
"ใบเสร็จรับเงิน/ใบกำกับภาษี" ให้ตอนบันทึกรับเงิน (VAT ตามสัดส่วนเงินที่รับ ครั้งสุดท้ายรับ VAT ที่เหลือทั้งหมด)
ถ้าลูกค้าต้องการใบกำกับภาษีตั้งแต่วันวางบิล ให้เลือก "ใบแจ้งหนี้/ใบกำกับภาษี" แทน เลขที่เอกสารออกตอนกด "ออกเอกสาร"
เพื่อให้เลขใบกำกับภาษีต่อเนื่องไม่มีช่องว่าง เอกสารที่ออกแล้วแก้ไขไม่ได้ ต้องยกเลิกหรือออกใบลดหนี้

**Phase 3 จัดซื้อ คลัง ต้นทุน และเจ้าหนี้**
- ผู้ขาย/ผู้รับเหมาช่วง ตรวจเลขผู้เสียภาษี ประเมินผู้ขาย (คุณภาพ ส่งตรงเวลา ราคา บริการ)
- ใบขอซื้อ (PR) → ขออนุมัติ → เปรียบเทียบราคาหลายเจ้า (ไฮไลต์ราคาต่ำสุดรายรายการ) → ออกใบสั่งซื้อ (PO)
- PO อนุมัติอัตโนมัติถ้าไม่เกินวงเงิน (ตั้งค่า `purchase.approval_threshold` ค่าเริ่มต้น 50,000) รับของบางส่วนได้ ยกเลิกใบรับได้
- คลังกลางและคลังหน้างาน ต้นทุนถัวเฉลี่ยเคลื่อนที่ เบิก/โอน/รับคืน/ปรับยอด สต็อกติดลบไม่ได้ สมุดคุมรายวัสดุ แจ้งเตือนต่ำกว่าจุดสั่งซื้อทุกเช้า 07:15
- สัญญาจ้างช่วง เบิกงวดตามผลงาน หักประกันผลงานและหัก ณ ที่จ่าย ตรวจรับแล้วตั้งหนี้อัตโนมัติ คืนเงินประกัน
- ค่าแรงรายวันต่อโครงการ (ไม่เกิน 1.5 แรงต่อคนต่อวันรวมทุกโครงการ) สรุปจ่ายเป็นงวด วันที่จ่ายแล้วถูกล็อก
- เจ้าหนี้: ตั้งหนี้จาก PO / งวดผู้รับเหมา / ค่าใช้จ่ายอื่น → อนุมัติ → ใบสำคัญจ่าย (ผู้สร้างอนุมัติเองไม่ได้) → จ่ายแล้วออก 50 ทวิ อัตโนมัติ
- ต้นทุนโครงการ งบ BOQ เทียบจริง ภาระผูกพัน กำไรคาดการณ์ ต้นทุนรายเดือน วัสดุใช้เกิน BOQ
- รายงานภาษีขาย ภาษีซื้อ ภ.ง.ด.3/53 รายเดือน (พิมพ์/CSV), กระแสเงินสดรายสัปดาห์
- พิมพ์ใบสั่งซื้อ ใบสำคัญจ่าย และหนังสือรับรอง 50 ทวิ (2 ฉบับ)

**Phase 4 ผู้บริหาร ปฏิทิน และงานหลังการขาย**
- แดชบอร์ดผู้บริหาร: วางบิล รับเงิน ต้นทุน กำไรขั้นต้น 12 เดือน, ลูกหนี้/เจ้าหนี้ค้างและเกินกำหนด, งานในมือ, เงินสด 4 สัปดาห์, โครงการล่าช้า/เกินงบ, อัตราปิดการขาย, ความพึงพอใจ และรายการที่ต้องดำเนินการ
- ปฏิทินรวม: นัดหมายที่บันทึกเอง + แผนโครงการ หมุดหมาย ติดตามลีด ใบเสนอราคาหมดอายุ งวดงาน ลูกหนี้/เจ้าหนี้ครบกำหนด ของเข้า ใบอนุญาตหมดอายุ นัดซ่อม (กรองตามสิทธิ์ผู้ใช้) และสรุป 7 วันข้างหน้าที่หน้าแรก
- ใบอนุญาตและเอกสารมีวันหมดอายุ (ใบอนุญาตก่อสร้าง ประกันภัย ภาษีรถ ใบประกอบวิชาชีพ ฯลฯ) แจ้งเตือน 08:00 เมื่อเข้าช่วงเตือน และอีกครั้งที่ 7 วัน 1 วัน วันหมดอายุ และทุกสัปดาห์หลังหมดอายุ ต่ออายุโดยเก็บประวัติฉบับเดิม
- รับประกันผลงาน: วันสิ้นสุด = วันส่งมอบจริง + ระยะรับประกันในสัญญา (ค่าตั้งต้น 12 เดือน แก้รายโครงการได้)
- งานแจ้งซ่อม: ตรวจระยะรับประกันอัตโนมัติ นัดช่าง เริ่มซ่อม ซ่อมเสร็จ (ต้นทุน/ค่าบริการนอกประกัน) ปิดงาน รูปก่อน/หลังจากกล้องมือถือ
- ความพึงพอใจลูกค้า: หลังบ้านบันทึกจากการโทร/เยี่ยม (ไม่มีหน้าลูกค้า) คะแนนรายด้าน แยกตามโครงการและ PM คะแนน 1–2 แจ้งผู้บริหารทันที
- ติดตั้งเป็นแอป (PWA) บนมือถือ/คอม แจ้งเมื่อมีเวอร์ชันใหม่ แสดงสถานะออฟไลน์ และรายงานประจำวันเก็บร่างในเครื่องเมื่อสัญญาณหลุด (ลบเมื่อบันทึกสำเร็จหรือออกจากระบบ)
- สำรอง/ส่งออกข้อมูล: หน้า "สำรองข้อมูล" ส่งออกทุกตารางเป็น ZIP ของ CSV (เลือกรวมไฟล์แนบได้) สำรองอัตโนมัติ 02:00 ลบไฟล์เก่าตามระยะเก็บ

## สำรองและกู้คืน

มี 2 ชั้น:

1. **สำรองเต็มรูปแบบสำหรับกู้ระบบ** (ผู้ดูแลเซิร์ฟเวอร์): `deploy/backup-db.sh` ใช้ `pg_dump` + `rsync` ไฟล์แนบ ตั้ง cron วันละครั้ง วิธีกู้คืนอยู่ท้ายสคริปต์
2. **ส่งออกข้อมูล** (ผู้มีสิทธิ์ `backup.manage` ในระบบ): ZIP ของ CSV เปิดด้วย Excel ได้ ไม่รวมรหัสผ่าน TOTP และ session
   เก็บที่ `KTT_BACKUP_DIR` (ค่าตั้งต้น production `/var/lib/ktt/backups`)

ทั้งสองแบบควรคัดลอกไปเก็บนอกเครื่องเซิร์ฟเวอร์เป็นประจำ

## สิ่งที่ไม่ได้ทำตามที่ตกลง

- ไม่เชื่อมโปรแกรมบัญชีภายนอก (ใช้รายงานภาษีและ CSV แทน)
- ไม่มีหน้าสำหรับลูกค้า (customer portal) ทุกอย่างทำผ่านหลังบ้าน
- ไม่ใช้บริการหรือบัญชีภายนอก (LINE, AI, คลาวด์) ระบบทำงานบนเซิร์ฟเวอร์ของบริษัทเอง
